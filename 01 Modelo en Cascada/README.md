# Modelo en Cascada

# Preguntas Grupo 1

## ¿Cuando es bueno utilizar el modelo cascada?
+ El modelo cascada es bueno utilizarlo cuando la planificacion es 100% rígida y com una vision clara y cerrada del producto final.
+ Requisitos inamovibles, osea sin cambios repentinos.
+ Su écito depemde de una definicion perfecta, no de la velocidad.
+ El cliente no cambiará el alcance una vez iniciado.
## ¿Cuales son las fase del modelo cascada?
+Fases del modelo cascada
+1. Requisitos (Fase fundamental):
Se realizan entrevistas y reuniones para definir exactamente qué se va a hacer. Se recopilan todos los requisitos, se documentan, se deciden las tareas, se establece el presupuesto y se asignan los responsables.
+2. Diseño y construcción:
Con los requisitos claros, comienza el trabajo técnico. En software, esto implica definir la arquitectura del sistema y comenzar la codificación (desarrollo) del producto.
+3. Fase de prueba:
Los especialistas prueban el producto desarrollado para detectar y corregir errores. El objetivo es asegurar que el entregable cumple exactamente con lo que el cliente pidió en la fase 1.
+4. Instalación / Implantación:
El producto sale a la luz y se despliega para su uso en el entorno real, cumpliendo con los estándares de la etapa de requisitos.
+5. Soporte y mantenimiento:
El producto es entregado oficialmente al cliente. Comienza una fase de soporte continuo para arreglar pequeños fallos futuros o mantener el sistema operativo según lo diseñado.

## ¿La diferencia del modelo cascada vs las metodología agiles?
+La primcipal diferencia entre el Modelo e Cascada y las Metodlogias Ágiles es que el modelo en cascada es lineal y secuencial, no ocurriendo cambios en la fase de planificacion del proyecto, mientras que las metodologias ágiles son interactivas y flexibles.
## ¿Cuales son las ventajas y desventajas del modelo cascada?
+Ventajas y desventajas-jose
 Ventajas
•	Es predecible: Los clientes saben desde el día 1 cuánto costará, cuánto tardará y qué recibirán exactamente.
•	Fácil de administrar: Al ser un modelo rígido, cada fase tiene entregables y fechas límite específicas.
•	Claridad para el equipo: Cada persona sabe exactamente qué tiene que hacer y cuándo.
•	Resistente a la rotación de personal: Como todo está hiper-documentado en la fase 1, si un programador renuncia, su reemplazo solo debe leer el documento para saber cómo continuar.
 Desventajas
•	Inflexibilidad total: Si se encuentra un error de requisito en etapas avanzadas, prácticamente hay que reiniciar el proyecto con código nuevo.
•	El cliente "compra a ciegas": Como las pruebas y la instalación están al final, el cliente no ve el producto real hasta que está casi terminado. Si no le gusta, ya es muy tarde para cambiarlo.
•	Mala para la incertidumbre: No sirve si el cliente solo tiene una "idea vaga" de lo que quiere.

## ¿Cual es el origen del modelo cascada?
+Aunque hoy en día es famoso en el mundo del software, sus verdaderos orígenes se encuentran en las industrias de la construcción y la fabricación física. En estos sectores, los cambios de último momento son financieramente desastrosos o físicamente imposibles (por ejemplo, no se puede construir el techo de una casa sin haber hecho primero los cimientos).
La primera descripción formal de este modelo adaptado al desarrollo de software fue redactada en 1970 por Winston W. Royce en un artículo sobre la gestión de desarrollo de software, sentando las bases de cómo se organizaría la industria en las décadas siguientes.
